# Kimi 球面投影方案核实、集成与实时性报告

日期：2026-08-29

## 结论

分享页提出的“视锥点云 → 球面角度深度图 → 平面通道图”适合作为局部感知与绕行引导层，但不能替代 FIRI 全局安全走廊。当前项目已按双频架构完成集成：低频 `full` 模式负责 FIRI/MVIE 全局路径，50 Hz `realtime` 模式只做低分辨率球面投影、有界候选搜索和精确 3-D 安全验证。

在当前 Intel i5-10400 / Python 3.11 环境，实时模式对 medium/high 各 100 个固定种子进行冷启动测试：medium 100/100 成功且全部小于 20 ms；high 99/100 成功且全部小于 20 ms。失败样本安全返回 `None`，不会输出碰撞路径。完整 FIRI/MVIE 从零计算仍约 0.5 s，不能宣称达到 20 ms。

## 对原方案的核实

### 可以直接采用

1. 用 `(theta, phi, range)` 解耦方向与距离。
2. 每个角度单元保留最近深度，形成球面深度图。
3. 障碍物安全膨胀量随距离增大而减小。
4. 从自由角度区域提取候选通道，并用通道宽度和转角排序。
5. 将投影层作为局部规划器或全局规划器的引导前端。

### 需要修正

1. 分享页称“半球投影”，但有限相机 FOV 实际只是球面上的一个角度窗口，不是完整半球。
2. `r_safe / (r * delta_theta)` 是小角度近似。实现使用 `asin(r_safe / r)`，并分别按水平和垂直角分辨率做二维膨胀。
3. 单帧角度图只能描述从当前视点可见的最近表面；它无法表示遮挡后的自由空间，不能独立保证全局可达。
4. 按图像行扫描得到的 graph 是方向通道图，不是完整三维位置图。它适合选择局部航向，不能直接替代世界坐标路径。
5. 分享页的 Jetson 30 Hz+ 是没有给出硬件、分辨率和实现证据的估计，不能用于论文性能结论。
6. Mercator 和 stereographic 对当前有限 FOV 实时避障没有必要；等角度网格更简单，也更容易建立固定计算预算。

## 当前实现

### 球面投影前端

- 通用点云接口：世界坐标点投影到最近深度角度图。
- 仿真接口：对 sphere、cylinder、cuboid 做解析射线求交。
- `25×17` 实时图和 `41×25` full 引导图。
- 距离相关二维安全膨胀。
- 行自由区间 navigability graph。
- 按目标转角和通道宽度排序候选方向。
- 所有候选最终必须通过原三维 point/segment 碰撞验证。

### 双频规划

- `plan_realtime`：20 ms 硬预算，最多一次局部修复；不调用 FIRI/MVIE/SLSQP；超时或无解返回 `None`。
- `plan_path`：低频全局层，包含投影引导、FIRI/MVIE、安全多胞体约束 SLSQP 和 fallback。
- `main.py` 默认使用 realtime，关闭绘图和性能图；论文出图或全局重规划时切换 `PLANNING_MODE='full'`。

### 同时修复的原规划缺陷

1. MVIE 改为带 Cholesky 因子的 log-det 约束优化，恢复平移不变性。
2. 轨迹优化约束 FIRI 安全多胞体端点，不再强迫 seed 进入不包含它的 MVIE 椭球。
3. `safety_margin` 统一为绝对米制净空，默认 0.30 m。
4. 后处理后重新计算碰撞状态。
5. sphere/cylinder/cuboid 的 point signed distance 改为正确的欧氏形式。
6. 段碰撞检查由 Python 逐点逐障碍循环改为 NumPy 批量计算，并移除原生几何已经覆盖时的冗余 KD 查询。
7. `main()` 在路径仍碰撞时返回失败，不再无条件报告成功。

## 20 ms 声明的边界

20 ms 指长期运行进程中的单次局部规划周期，不包括 Python/Matplotlib/Open3D 首次导入、仿真场景随机生成、论文绘图和低频全局 FIRI 重规划。默认 `main()` seed 0 的计时器结果为：路径规划 5.33 ms，从场景清理到结果保存的内部总时间 9.68 ms；独立 Python 进程启动仍受依赖导入时间影响。

若要求“每帧从深度图开始重新计算完整 FIRI/MVIE/SLSQP，并且端到端严格小于 20 ms”，当前 Python/SciPy 技术栈不满足。需要把射线投影、碰撞几何、FIRI 和优化器下沉到 C++，采用预分配内存、增量走廊更新和异步全局/局部线程。
